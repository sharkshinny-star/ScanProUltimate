# Trimmed OpenCV

The app ships its own OpenCV build in the `:opencv` module instead of the Maven artifact
`org.opencv:opencv`. The Maven artifact links every OpenCV module into one native library
(about 25 MB for arm64 alone); the app only calls `core`, `imgproc` and `photo`, so the trimmed
build is a fraction of the size with no change to the calls the app makes.

| Contents | Where |
|---|---|
| Java bindings (generated by OpenCV's own generator) | `opencv/src/main/java/org/opencv` |
| `libopencv_java4.so` (built here) and `libc++_shared.so` (from the NDK) per CPU type | `opencv/src/main/jniLibs/<abi>` |
| Build recipe | `scripts/opencv/build-opencv-android.sh` |

## Rebuilding (for an OpenCV upgrade)

1. Check out the OpenCV tag named in the script: `git clone --depth 1 --branch 4.14.0 https://github.com/opencv/opencv.git`
2. Install an Android NDK (r27 or newer) and point `ANDROID_NDK` at it; have `cmake`, `ninja` and `python3` on the path.
3. Run `scripts/opencv/build-opencv-android.sh <opencv-checkout> <output-dir>` (about 10 minutes per CPU type).
4. Copy `install-<abi>/sdk/native/libs/<abi>/libopencv_java4.so` and the NDK's `libc++_shared.so` for that ABI
   (`<ndk>/toolchains/llvm/prebuilt/*/sysroot/usr/lib/<triple>/libc++_shared.so`, run through `llvm-strip --strip-unneeded`) into `opencv/src/main/jniLibs/<abi>/`, and
   `install-arm64-v8a/sdk/java/src/org` over `opencv/src/main/java/org` (the Java sources are the same for every ABI;
   drop the two `.kt` files, the Kotlin extensions are not used). Then delete the camera view classes in
   `org/opencv/android` (everything except `OpenCVLoader`, `StaticHelper` and `Utils`) and the `loadResource`
   methods in `Utils.java`: they need the videoio and imgcodecs modules, which are not built, and the app's
   scanner uses CameraX instead.
5. Build the app and run the scanner once: document detection, filters and finger removal cover the three modules.

If the app starts using another OpenCV module, add it to `BUILD_LIST` in the script and rebuild.

## Desktop build for the imaging tests

`MatFiltersTest`-style tests (`app/src/test/java/com/example/scanpro/imaging/MatFilters*Test.kt`) run the real
filters on a desktop JVM, so they need a desktop build of the same OpenCV. It is vendored at
`app/src/test/resources/native/linux-x86_64/opencv_java4.bin` (a stripped Linux x86_64 shared library; the
extension is `.bin` because the Android Gradle plugin drops `.so` files from test resources). The tests load it by
path, skip themselves on other platforms, and fail, not skip, if it can't be loaded on Linux x86_64.

Rebuild it with `scripts/opencv/build-opencv-host.sh <opencv-checkout> <output-dir>` when OpenCV is upgraded, then
copy the stripped `libopencv_java*.so` over the `.bin`.

The tests compare the OpenCV filters with the algorithms they replaced (colour matrix, whiteboard, adaptive
threshold) and with golden images in `app/src/test/resources/golden`. After an intended change to a filter, review
the new pictures and accept them with:

```
./gradlew :app:testDebugUnitTest --tests '*MatFiltersGoldenTest*' -Pscanpro.updateGoldens=true
```
